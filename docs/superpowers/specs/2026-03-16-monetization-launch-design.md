# VibeStudy Monetization Launch Design

**Дата:** 16 марта 2026  
**Статус:** draft for execution  
**Продукт:** VibeStudy  
**Цель:** довести текущий AI-learning MVP до платного soft launch, на котором можно получить первые деньги и проверить спрос.

## 1. Контекст

Текущий проект уже умеет:
- авторизовывать пользователя через Supabase;
- генерировать уроки через Edge Function и OpenAI;
- хранить и показывать прогресс;
- закрывать приватные роуты;
- давать базовый onboarding через `Home` и `Profile`.

Текущий проект ещё не готов к заработку, потому что:
- нет платного контура;
- часть пользовательского опыта всё ещё выглядит как MVP;
- отсутствует прозрачная модель entitlement;
- нет сквозной аналитики воронки;
- нет простого способа понять, что приводит к оплате, а что нет.

## 2. Продуктовая гипотеза

VibeStudy должен запускаться не как "универсальная школа программирования", а как:

**AI daily coding coach для новичков и джунов, где за 15-25 минут в день человек реально пишет код, видит прогресс и постепенно доходит до первого проектного результата.**

Это означает:
- короткий ежедневный формат;
- живая практика, а не только теория;
- AI как помощник и ревьюер, а не как единственная ценность;
- бесплатный первый value loop до paywall;
- простой и честный тариф.

## 3. Целевая аудитория

Первый запуск ориентирован на:
- русскоязычных новичков;
- джунов, которым нужен дисциплинированный ежедневный режим;
- людей, которые хотят войти в разработку через `Python`, `JavaScript` или `Go`.

Не целимся в:
- senior-level interview prep;
- enterprise B2B;
- длинные академические программы;
- "сертификат как основной value proposition".

## 4. Что должно продаваться

Пользователь платит не за "доступ к AI", а за:
- структурированный путь;
- возможность не терять прогресс;
- AI hints и AI review;
- mini-project checkpoints;
- понятное ощущение роста;
- доступ ко всем трекам и расширенной аналитике.

## 5. Основной value loop

Пользовательский цикл, который должен работать идеально:

1. Пользователь входит в аккаунт.
2. Проходит короткий onboarding.
3. Выбирает трек.
4. Открывает первый урок.
5. Читает теорию и решает хотя бы одну задачу.
6. Получает XP, обновление streak и сохранённый прогресс.
7. Возвращается на следующий день.

Этот цикл должен быть бесплатным до первого ощутимого результата.

## 6. Launch scope

### 6.1 Что входит в launch

- `Auth`: Google + email magic link.
- `Onboarding`: выбор цели и языка.
- `Tracks`: только `Python`, `JavaScript`, `Go`.
- `Lessons`: первые 7 дней каждого трека доведены до высокого качества.
- `AI`: генерация урока, hints, review summary.
- `Progress`: честный XP, streak, completed lessons, completed tasks.
- `Profile`: реальные данные аккаунта и управление состоянием.
- `Paywall`: один понятный платный тариф.
- `Billing`: подписка и entitlement.
- `Analytics`: события по воронке.
- `Support`: контакт и канал обратной связи.
- `Legal`: политика конфиденциальности и оферта.

### 6.2 Что не входит в launch

- marketplace;
- community/forum;
- сертификаты;
- B2B seat management;
- сложные social features;
- многоуровневые тарифы;
- полноценная мобильная нативная версия.

## 7. Функциональное ТЗ

### 7.1 Authentication

Пользователь должен иметь возможность:
- войти через Google;
- войти через magic link;
- восстановить сессию после refresh;
- корректно выйти из аккаунта;
- не видеть утечки прогресса между аккаунтами.

### 7.2 Onboarding

После первого входа пользователь должен:
- выбрать цель:
  - найти первую работу;
  - учиться для себя;
  - перейти в новый стек;
- выбрать язык;
- получить рекомендованный первый урок;
- понять, что он получит бесплатно, а за что будет платить.

### 7.3 Lessons

Урок должен включать:
- теорию;
- практические задачи;
- AI hint по задаче;
- краткий AI review после выполнения;
- сохранение прогресса;
- resume flow.

Если генерация падает:
- экран не ломается;
- пользователь видит fallback и понятное сообщение;
- повторная попытка не ведёт к потере контекста.

### 7.4 Progress

Система должна хранить:
- `total_xp`;
- `level`;
- `current_streak`;
- `longest_streak`;
- `completed lessons`;
- `completed tasks`;
- `active tracks`.

На UI нельзя показывать выдуманные значения.

### 7.5 Profile

Экран профиля должен показывать:
- состояние аккаунта;
- активные треки;
- реальные KPI пользователя;
- статус подписки;
- историю использования;
- reset flow для тестового/демо режима.

### 7.6 Paywall

До оплаты пользователь получает:
- onboarding;
- доступ к одному треку;
- первые 3 дня;
- ограниченное число AI hints в день.

После оплаты пользователь получает:
- все треки;
- все дни;
- AI review;
- mini-project checkpoints;
- расширенную аналитику;
- приоритетную генерацию.

### 7.7 Billing

Нужно:
- один тариф;
- прозрачная цена;
- auto-renew с явным объяснением;
- отмена без скрытых шагов;
- серверная проверка entitlement;
- синхронизация статуса подписки с UI.

### 7.8 Analytics

Обязательные события:
- `signup_completed`
- `onboarding_completed`
- `track_selected`
- `first_lesson_started`
- `first_task_completed`
- `day_2_returned`
- `paywall_viewed`
- `checkout_started`
- `subscription_started`
- `subscription_renewed`
- `subscription_canceled`

## 8. Нефункциональное ТЗ

- Никаких критичных моков в `Home`, `Profile`, `Lessons`, `Analytics`.
- Все приватные данные защищены RLS.
- Все платёжные права проверяются на backend.
- Все ключевые сценарии покрыты smoke/e2e тестами.
- Ошибка оплаты или AI не должна убивать сессию пользователя.
- Доступность: читаемые empty states, понятные ошибки, прозрачные CTA.

## 9. Бизнес-модель запуска

### 9.1 Формат запуска

`Soft launch`

Цель:
- первые 50-100 пользователей;
- первые платящие клиенты;
- измерение воронки;
- корректировка onboarding и paywall на основе данных.

### 9.2 Метрики запуска

Ключевые метрики:
- `% пользователей, завершивших onboarding`
- `% пользователей, начавших первый урок`
- `% пользователей, решивших первую задачу`
- `% пользователей, вернувшихся на второй день`
- `% пользователей, открывших paywall`
- `% пользователей, начавших checkout`
- `% пользователей, завершивших оплату`

## 10. Критерии готовности к monetization launch

Проект готов к soft launch, когда:
- пользователь без помощи проходит путь `sign up -> onboarding -> lesson -> task -> progress -> paywall -> checkout`;
- UI не врёт о прогрессе;
- есть один рабочий платный тариф;
- entitlement завязан на backend;
- есть события аналитики;
- есть support/legal pages;
- нет известных P1-багов в auth, lessons, progress, billing.

## 11. Главные ошибки, которых нужно избежать

- Слишком ранний paywall до первого value.
- Непрозрачные или запутанные тарифы.
- Продажа "AI" вместо продажи результата.
- Ложные метрики и моки в аккаунте.
- Нестабильная генерация уроков.
- Отсутствие resume flow.
- Отмена подписки через боль.
- Отсутствие аналитики на момент запуска.

## 12. Рекомендованный порядок реализации

1. Стабилизировать core learning loop.
2. Ввести onboarding и free-to-paid границу.
3. Добавить billing и entitlement.
4. Привязать аналитику ко всей воронке.
5. Подготовить legal/support/admin.
6. Провести soft launch.
